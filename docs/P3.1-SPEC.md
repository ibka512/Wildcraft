# P3.1 背负装备与探索界面规格

日期：2026-10-02。版本 `0.1.0-dev.5`。实际使用登记已由用户确认；HUD 按用户最新决定采用左上角红心、下方精力，覆盖最初的经验条区域切换建议。实现与本机验证见 [验收记录](P3.1-VERIFICATION.md)。

## 已确认的使用规则

**实际使用后登记**，单纯切换快捷栏不更新历史：

| 分类 | 登记动作 | 不登记的动作 |
| --- | --- | --- |
| 剑/斧 | 服务端确认造成伤害的玩家近战攻击；斧成功完成削皮等操作 | 切到手中、空挥、无效操作、荆棘反伤 |
| 盾 | 实际进入举盾状态 | 仅持有、仅放副手 |
| 弓/弩 | 实际拉弓/装填；预装填弩实际发射 | 仅持有、缺少弹药而不能使用 |

三个视觉槽只记录现有装备，不增加库存容量。滑翔伞仍只有原来的一个真实装备槽，不增加第四个背负槽。

## 所有权与保存

每类只记录最近一件装备。服务端掌握登记和失效，客户端负责显示。运行中跟踪真实堆栈、位置和组件签名；原版菜单事务前后能唯一确认的移动才更新引用。不能把另一把同名、同 ID、同外观的剑当成原来那把。无法可靠确认时清空显示，等下次实际使用。

掉落、放箱子、消耗、损坏、死亡、重登和切维度均验证归属。耐久、染色和模型组件改变时读取当前物品；不在渲染帧扫描整个背包。不预先给所有原版物品增加 UUID。

保存使用独立格式 1 附件，旧玩家默认空记录，保留既有精力与伞槽格式。重载只检查已保存位置，不从签名创造或恢复物品；没有迁移个人世界。向跟踪范围内的观察者只同步显示白名单，不发送全背包、名称、私人容器或任意嵌套组件。Fuse 模型能力以后明确扩展。

## 显示规则

| 场景 | 显示结果 |
| --- | --- |
| 正常持握 | 已在主/副手显示的同一真实装备不背负，其他已登记装备可以显示；手持同款备用装备不误隐藏原记录 |
| 滑翔 | 双手持伞，真实装备仍在原格子；已登记且仍拥有的物品可背负 |
| 拉弓/装弩 | 手中弓不再背负；盾暂时收纳到背部，不叠在拉弓双手上；真实副手库存不移动 |
| 第一人称 | 不绘制自己的背负，其他玩家仍可见 |
| 第三人称 | 复用当前允许的物品模型组件，跟随身体、潜行和游泳姿势 |
| 鞘翅 | 鞘翅优先，隐藏冲突的盾和弓/弩；近战可保留，可能被翼遮挡；完整腰侧适配留到后续 |
| 可见披风 | 首版披风占用同一挂点，隐藏三类背负；关闭披风显示后恢复，不清除记录 |
| 护甲、宽/窄模型 | 原版身体挂点；已完成最低展示检查，第三方大模型不承诺兼容 |

首版不增加拔出/收回动画，不延迟真实快捷栏切换。斜跨近战、反向斜跨弓和偏置盾的尺寸依据游戏截图确定。服务器决定真实手/背互斥，网络变化依正常同步到达；不以客户端外观匹配再次推测身份。

## 左上角 HUD

原版红心放在左上角，精力数值与短条放在红心下方；额外红心与吸收向下排成多行，精力位置随其底边移动。红心继续使用原版伤害闪烁、中毒、凋零、吸收和极限状态图案。

攀爬/滑翔、精力未满和恢复期间显示精力；补满后约 2 秒隐藏。普通走路、跳跃、疾跑和游泳不新增费用。历史峰值继续保存；原版经验与当前等级、骑乘跳跃条保留底部位置，不用峰值替代当前等级。满精力时单纯更改经验等级不弹出精力条。

已检查低精力、中英文、大数值、GUI 缩放、红心多行、骑乘、隐藏 HUD 和死亡相关显示。温度后续使用小型提示；林克时间继续共用精力，不增加专属资源条。

## 验收合同

1. 服务端登记与真实引用：同款两把剑、移动、丢弃、箱子、组件变化和损坏。
2. 独立保存与最小同步：死亡、保留物品、重登、维度和重新进入观察范围。
3. 原版渲染、手/背互斥、滑翔收纳、双手拉弓、披风/鞘翅最低规则。
4. 左上角红心与精力；原 P1/P2/P3 行为保持。
5. 两个独立图形客户端实际互相观察，完成变化、失效和重连；单客户端 TCP 不替代此项。
6. 相关自动测试、成品包和不安装测试模组的独立服务端，输出本地开发包。
