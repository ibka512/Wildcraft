# P3.1 背负装备与融合 HUD 规格

日期：2026-10-02。状态：登记规则已由用户确认，R1 渲染入口已验证；正式功能尚未实现。

## 已确认的使用规则

**实际使用后登记**，单纯切换快捷栏不更新历史：

| 分类 | 登记动作 | 不登记的动作 |
| --- | --- | --- |
| 剑/斧 | 服务端确认的近战攻击；斧成功完成削皮等操作 | 切到手中、空挥或无效操作 |
| 盾 | 实际进入举盾状态 | 仅持有、仅放副手 |
| 弓/弩 | 实际拉弓/装填；预装填弩实际发射 | 仅持有、缺少弹药而不能使用 |

三个视觉槽只记录现有装备，不增加库存容量。滑翔伞仍只有原来的一个真实装备槽，不增加第四个背负槽。

## 所有权与保存

每类只记录最近一件装备。服务端掌握登记和失效，客户端负责显示。优先跟踪真实堆栈、格子和组件信息；库存事务可确认的移动才更新引用。不能把“另有一把同名剑”当成原来那把。无法可靠确认时清空显示，等下次实际使用。

掉落、放箱子、消耗、损坏、死亡、重登和切维度均验证归属。耐久、染色和模型组件改变时读取当前物品；不在渲染帧扫描整个背包。不预先给所有原版物品增加 UUID。

正式保存使用独立附件，旧玩家默认空记录，保留既有精力与伞槽保存格式。先在专用世界中验证重载；不迁移个人世界。向观察者只同步显示所需的数据，不发送整个背包、私人容器或任意嵌套组件。Fuse 模型能力以后明确扩展。

## 显示规则

| 场景 | 显示结果 |
| --- | --- |
| 正常持握 | 已在主/副手显示的同一件物品不背负，其他已登记装备可以显示 |
| 滑翔 | 双手持伞，真实装备仍在原来的格子；已登记且仍拥有的物品可背负 |
| 拉弓 | 手中弓不再背负；盾不重复叠在拉弓双手上，其他装备按挂点显示 |
| 第一人称 | 不绘制自己的背部装备，其他玩家仍可见 |
| 第三人称 | 复用当前物品模型，跟随身体、潜行和游泳姿势 |
| 鞘翅 | 鞘翅优先，隐藏冲突的盾/大型弓；完整腰侧适配留到后续 |
| 披风、护甲、宽/窄手臂 | 完成最低展示检查；严重冲突采用明确隐藏规则，记录限制 |

首版不增加拔出/收回动画，不延迟真实快捷栏切换。斜跨近战、反向斜跨弓和偏置盾的实际尺寸由游戏截图确定，R1 挂点截图只作为技术样例。

## HUD 切换

经验和精力使用原版经验条所在区域。攀爬/滑翔等特殊消耗、等待恢复和恢复过程中显示精力；补满后短暂保留，再恢复原版当前经验和等级。历史峰值保存在玩家数据中，不用峰值替代当前经验等级。普通走路、跳跃、疾跑和游泳不产生费用。

原版骑乘跳跃条等场景保留其必要信息，不能一律遮挡。后续专注与料理通过同一个呈现规则接入，不增加各自独立的资源条。验证低精力、中英文、大数值、窗口缩放、死亡、旁观和隐藏 HUD。

## 具体实现与验收顺序

1. 服务端登记和可靠引用；先验同 ID 两把剑、移动、丢弃、箱子和损坏。
2. 独立保存与最小显示同步；验死亡、保留物品、重登、切维度和重新进入观察范围。
3. 原版物品渲染、手/背互斥、滑翔收纳，以及披风/鞘翅最低兼容。
4. 融合经验/精力 HUD；原 P1/P2/P3 行为保持。
5. 两个独立图形客户端实际互相观察，完成截图和状态失效检查；单客户端 TCP 测试不能替代这项验收。
6. 相关自动测试、成品包和独立服务端检查，记录支持范围并输出下一版安装包。
