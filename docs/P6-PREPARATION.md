# P6 机械安装开发准备

2026-10-04。R0已经证明单实体主体、原版碰撞与乘坐、有限节点、一次性安装、满库存不丢物品，以及跨区块/重载可行，见R0-FINDINGS。正式实现必须使用新正式类型，不能把测试命名空间和研究开关打进运行包。P5已提供真实电池组件与有限消费函数，不重新建立电池存储格式。

## 等待确认的操作

已向用户询问：直接指向节点（手持部件右键安装、蹲下空手拆下、就近预览），或专用工具打开节点菜单。此选择影响输入和安装流程，尚未收到答案。只准备不依赖此决定的部分，不把预选当成同意。

## 可执行的下一批

1. 正式单实体机械主体，采用原版移动、碰撞、乘坐；保留简化轴对齐碰撞，暂不引入物理库。
2. 建议六个固定节点（上下及四侧），稳定编号和本地方向；节点占用、距离、实际手持物品、创建者所有权由服务端确认。主体尺寸及节点坐标在实际模型/碰撞场景校准，不开启任意方块自由组合。
3. P6先支持原创风扇物品与P5电池，至少走完“安装→供能→移动→停止→拆下→再安装”循环；每台最多一个电池。P7再加入其他六类部件，不将风扇切片当作全部机械完成。
4. 完整ItemStack保存部件，电池费用只从实际安装堆栈扣除，返回副本仅用于显示。带在机械上的红石块没有无限能源资格。不得恢复或生成材料签名来凭空取物。
5. 回收先检查真实库存容量，再转移一次；原版创造模式Inventory.add在满库存时可丢弃输入，必须保留R0已发现的保护。重复、越界、占用、超距、其他玩家操作和并发竞争要拒绝且不消费。
6. 同步仅给跟踪者发送必要节点外观/工作状态，不同步玩家背包；客户端只发动作意图，不报电量或最终位置。实体注册、部件模型、节点提示与中英文资源进入正式生成/资源流程。
7. 从原版碰撞路径校准动力、重力、速度上限与乘坐位置；电池耗尽停止推力，不能让风扇掩盖地形碰撞或提供无限悬空。
8. 保存稳定格式1的节点真实物品、创建者、方向和开关；区块卸载不计算离线费用。重载检查电量不回满、部件不复制、位置和运行行为正确。

## 验收场景

| 场景 | 要验证的结果 |
| --- | --- |
| 真实安装/拆卸 | 手持物品扣一次，满库存保持安装，腾空后回收一次，电量保持 |
| 主体运动与玩家 | 碰墙停止、不穿地；乘客随主体移动，耗尽后不继续获得推力 |
| 方向与节点 | 六节点索引、占用和安装方向一致，预览不是任意远程搬运 |
| 保存与区块 | 安装清单、方向、电量和主体位置重载稳定，没有离线回满 |
| 两位玩家 | 同时装同一节点只成功一次，非所有者不能取走部件 |
| 固定与移动能源 | 先在充电器充电再安装；随身红石块没有无限供电 |
| 正式包 | 有实际模型、提示和操作说明；独立服务端无客户端类，原有玩法回归 |

P7仍需在该阶段确定火箭一次性消耗/可补充、浮力介质等重要玩法边界。当前没有正式机械，R0实验不可作为成品安装。
