## 客户端与服务端

图集、模型、动画、准星、声音、后处理和设置页均在客户端表现边界内；生命、精力、输入、攻击、物品使用、滑翔中断和原版库存规则保持原合同。关闭滤镜仍不会关闭林克时间或计费。

新增两个**非持久化**展示附件：

- `climb_visual` 向附近观察者提供抓墙是否有效、墙面方向和实际移动类型，不提供精力、输入包或私有保存信息。
- `back_equipment_visual` 提供三类已登记真实引用的会话标识与归属（隐藏/主手/副手/背部），不暴露库存槽位、保存签名或私有组件。标识只用于本次会话，不能恢复或生成物品。

背负的显示副本继续使用原来的组件白名单；动画不通过名称、模型相同或物品 ID 判断身份。换上外观相同的备用剑不改变原引用。丢弃、损坏、失去引用立即移除，无离手残影；攻击、拉弓、举盾立刻使用原版手持姿态。可见披风、鞘翅、隐身、旁观及自己的第一人称仍先应用既有隐藏规则。

持久化 `player_stamina`、专用伞槽、三类背负引用及客户端画面设置均保持格式 1，无真实存档迁移。新附件不保存；旧客户端不属于新展示协议的兼容测试范围，联机测试使用相同 Mod 版本。

## 资源转换与再生成

```sh
python3 art/tools/bake-paraglider-mesh.py
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --disable-autoexec --python art/tools/bake-character-poses.py -- "$PWD"
./dev.sh runDatagen
./dev.sh build
```

Blender 路径可替换为自己的安装位置，依赖不进入正式 JAR。脚本不执行源稿内的脚本，不保存源稿。精力图集、物品/空槽图标、品牌图标、伞纹理和 OGG 按交付原字节复制；语言与后处理 JSON 由已有数据生成器维护。

网格将设计坐标 `(x,y,z)` 转为原版玩家模型 `(x,24-y,z)/16`，反射 Y 后反转面顶点顺序，UV 不变。原版网格提交通道保留正确光照与法线；第一人称只绘制最后三部分木架/握柄，避免整张伞面挡住视野。

角色动画将 Blender 坐标转成原版 ModelPart 局部姿态，使用 Blender XYZ 分解对应游戏的 rotationZYX(z,y,x)，显式启用隐藏的细手臂模型求值，扣除标准/细手臂的原版立方体中心偏移；排除预览专用父节点的位移，防止动画再次移动真实玩家。开伞过渡停在稳定握持帧，释放立即交还玩法与手持动作；攀爬方向和翻顶状态由服务端实际接触/位移提供，身体跟随墙面，镜头仍由玩家控制。

背负挂点按实际模型边界取中心，盾的默认 FIXED 比例 .55 单独补偿；剑/斧 .85、弓/弩 .9，与原版第三人称手持比例一致。第三方重写 FIXED 显示变换的物品模型仍需独立适配验证。

## 验证与交付

运行完整验收：先 `runDatagen`，再 `./dev.sh build runGameTest runPackagedClientTest -PacceptMinecraftEula=true`。该属性仅适用于已经明确同意 Minecraft EULA 的测试操作者。美术问题可用 `./dev.sh runCoreArtClientTest` 单独复测；它仍使用真实生产客户端与正式 Wildcraft JAR。

最终结果、截图、哈希与安装包见 [本阶段验证](CORE-ART-VERIFICATION.md) 和 `development-assets/verification/core-art-v1`。标准/细手臂握点数值检查、普通皮肤实际画面和生产图形编译是不同证据，不能互相替代。

尚未作为完成项：真实账号披风、任意第三方模型/动画模组、长时间高延迟联机、不同设备的视角与音量偏好。新的循环只覆盖交付的四肢动作；不引入弯曲关节骨骼、全身 IK、抓取路径、环形精力、腰侧披风布局或新玩法。后续如要这些能力需要单独设计。
