## 资源与实现入口

- 原稿在 `art/production-v2/<编号>/<版本>/`。`tools/import-second-art.py` 只读取源稿，输出运行资源；重新导入需要 Python 3 和 Pillow。普通构建不需要 Pillow、Blender 或 Aseprite。
- `src/main/resources/assets/wildcraft/second-art-provenance.json` 记录 48 个原样复制文件的来源、目标与 SHA-256；网格、动态电池遮罩是派生资源，单独由导入工具生成。
- 方块模型及 GUI 底图保留交付原字节。网格烘焙处理节点旋转、非四边形和 UV；模型单位及 UV 均除以 16，128×64 图集不再额外缩放。
- `SecondArtModelProvider` 生成四料理分流与电池 GUI 电量模型；手持、掉落等上下文使用 `BatteryItemRenderer`。翻译输入在 `src/client/resources/wildcraft-datagen-labels.json`；资源生成与构建分两次执行。
- `ArtGui`、料理/温度 HUD 和三个菜单负责显示；`ArtMesh`、`ArtBlockRenderer`、`MachineRenderer` 负责世界网格、动态面板与透明预览。预览保留深度测试、关闭深度写入，不能透过墙体。
- `FusionPresentation`、`FusionItemRenderer`、`FusionArrowRenderer` 与 `FusionSlotMarkMixin` 负责模型和角标。角标只在有效公开融合视图存在时绘制，拆除或耗尽立即消失；脱离宿主的材料 wear 仍以文字提示。
- `CharacterPoses` 使用每玩家局部姿态快照与四肢插值，复用每帧原版姿态；不保存世界矩阵、不延迟攻击与使用。腰侧布局由 `BackEquipmentLayer` 根据披风/鞘翅选择，不增加装备槽。

## 服务端边界

料理锅、充电器、制造机通过原生方块实体数据包同步有限 `WildcraftArtSnapshot`。只有状态、充电余量和是否有电池；库存、料理结果及制造机私有待产物不在该视图中。初始区块加载和后续更新使用同一路径，保存仍走原有格式。

`ArtFeedback` 只广播已提交事件：料理实际开始/完成、真实充电开始/满电、机械成功安装/回收/工作切换、制造实际付款/产物转入输出、Fuse 成功事务和实际命中特效。恢复存档不重放开始音，失败操作不播放成功音。

客户端按维度和序号去重：最多 6 个新短音、同类 2 个、每来源 1 个，无排队；安装/拆卸轻微随机音高，其他固定。粒子每事件最多 6、每来源 12、全局 48，寿命 6/8 刻，尊重粒子设置，避开近脸与准星中心。断线、换维度、过期和来源消失清理；来源跟踪允许 100ms 到包宽限。

## 仍需持续观察的边界

- 采用模型完整保留尺寸。主体仍只有既有 1.4×0.65 AABB；底部部件可能进入地面，侧装轮存在约 0.075 格视觉间隙。本次不扩展为逐部件刚体碰撞，人工路面与组合手感仍需后续复核。
- 料理锅采用交付锅体；交付未提供可直接运行的汤面变体，本次没有新增汤面动画。热源、料理界面和状态保持真实规则。
- 原版宿主、附魔、盾纹、染色及测试材料覆盖不等于任意第三方自定义渲染器兼容。缺失根模型、无效边界与不可用材料使用回退；嵌套第三方模型异常仍需兼容测试。
- Blender/Aseprite 的审稿预览不是实机证据；自动图形回归不替代长时间生存、多人声音混音和连续动作的人工手感验收。实际执行结果见 [验证记录](SECOND-ART-VERIFICATION.md)。
