## 进入顺序

1. 固定一个已实际归档的本机版本；记录Minecraft26.3、Fabric/JDK环境、游戏设置、按键和当前已支持动画范围。用新建正常单人生存或明确的测试世界副本，不迁移真实存档、不删除旧数据。限制源动画不阻止先检查现有原生玩法，但须标明视觉旧路径。
2. 执行SINGLEPLAYER-PLAYTEST.md原八项正常获取/制作/料理/探索/Fuse/能源/机械/制造/保存流程，追加下面的战斗和交接检查。命令给材料、布置平台和定位的自动世界只作守恒/操作验证，不当从零生存或人工手感结果。
3. 按实际失败建立最小复现；区分功能错误、操作困惑、数值体验和资产不足。先修功能错误和说明，定向平衡需依据具体距离、频率、时间与消耗，不由理论续航表直接改成长、容量或费用。
4. 验证修改涉及的边界与旧路径；同一错误的红/绿及同一次使用的伤害/弹药/耐久/Fuse结算一起保存。只有实际改动或新的失败/风险才扩大回归；没有清晰结果不发布候选。

## 战斗与探索交接补充

默认键以实际游戏改绑设置为准：G攀爬、Z锁定、左右方括号切目标、C防御、X侧后跳、H手动技能确认、F8设置、V融合、R机械启停；原版跳跃键空中再次按开收伞，取用物品收伞。记录误触、松开是否即时响应、视野遮挡和暂停/背包后的恢复。

- 普通攻击、蓄力/取消、原盾防御、完美格挡和闪避：保持原生一次命中/耐久/Fuse；逐项记录费用与连续操作是否顺畅。动画与真实命中窗口分开判断，不把画面拉长当技能生效时间。
- 左右真实主手及主/副手实际用弓：检查准星与瞄准、一次箭/弹药/耐久、进入和退出、空中技能自动/手动/关闭；先使用已实际验证的版本范围，尚未接入的RIGHT空中或正式第一人称使用原路径，不填“通过”。
- 真攀爬→松手/开伞→取弓→空中使用/落地→地面攻击；普通低跳开伞可能在持续姿态出现前合法落地收伞，持续hold另在安全高处验证。开伞视觉双手与真实库存/装备位一致，取物立即交出伞。
- 真实快捷栏、F手间交换、背包换装、原生弓弩使用、进食和挖掘；不得由记忆背负复制物品或在取消后补发攻击。盔甲/披风/鞘翅复杂姿态单独记录支持范围与视觉问题。
