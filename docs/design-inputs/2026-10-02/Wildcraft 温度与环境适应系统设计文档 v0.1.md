## Wildcraft 温度与环境适应系统设计文档 v0.1  
## 1. 功能定位  
Wildcraft 的温度系统用于让 Minecraft 世界中的不同生物群系、天气和局部环境具备更明确的“冷热感”。  
该系统不定位为硬核生存机制。  
核心目标是：  
让温度成为环境信息和探索反馈，而不是让玩家持续被温度管理绑架。  
因此，绝大多数冷热变化只影响环境表现、HUD 和部分料理效果，不直接对玩家造成伤害或强制负面状态。  
  
## 2. 核心设计原则  
## 2.1 温度首先是环境信息  
玩家进入：  
* 雪原  
* 沙漠  
* 丛林  
* 海洋  
* 地下  
* 下界  
时，可以感受到环境温度不同。  
但这种差异首先表现为：  
* 温度数值变化  
* HUD 提示  
* 视觉反馈  
* 环境氛围  
而不是：  
一进沙漠就掉血，一进雪原就减速。  
  
## 2.2 不破坏 Minecraft 生物群系设计  
Minecraft 原版中的生物群系主要承担：  
* 景观差异  
* 资源差异  
* 生态差异  
* 探索差异  
Wildcraft 不应该把它们全部变成：  
“你没准备对应抗性就不能去。”  
因此普通生物群系温度默认不会：  
* 持续扣血  
* 禁止疾跑  
* 大幅降低移动速度  
* 强制玩家穿特殊装备  
* 强制频繁进食  
* 持续叠加负面状态  
  
## 3. 温度结构  
玩家当前环境温度由多个部分组成：  
```
当前环境温度
=
生物群系基础温度
+
天气修正
+
局部环境修正
+
特殊区域修正
```
其中最主要的是：  
**生物群系基础温度。**  
  
## 4. 生物群系基础温度  
每个生物群系拥有自己的基础环境温度。  
例如：  
```
雪原
→ 极冷

针叶林
→ 偏冷

平原
→ 温和

森林
→ 温和

丛林
→ 温暖

恶地
→ 炎热

沙漠
→ 炎热

下界
→ 极热
```
具体数值在开发和平衡阶段确定。  
第一版重点是建立：  
**相对冷热关系。**  
不要求追求现实温度。  
  
## 5. 温度等级  
建议将环境温度划分为几个较宽的等级。  
例如：  
```
极冷
寒冷
偏冷
舒适
偏暖
炎热
极热
```
避免温度系统过度精细。  
玩家应该能够快速理解：  
这里比较冷。  
而不是需要管理小数点温度。  
  
## 6. 局部环境温度  
生物群系只决定基础温度。  
局部环境可以临时改变当前读数。  
  
## 7. 岩浆  
玩家靠近岩浆时：  
```
当前温度
↑
```
距离越近，升温越明显。  
但默认：  
**岩浆附近升温本身不会额外伤害玩家。**  
真正的危险仍然来自 Minecraft 原版：  
* 接触岩浆  
* 火焰  
* 燃烧  
* 火焰伤害  
Wildcraft 不额外制造“热死”机制。  
  
## 8. 水  
玩家进入水中时：  
```
当前温度
↓
```
水体会产生明显降温效果。  
但普通情况下：  
**水中降温不会直接给玩家负面状态。**  
它主要用于：  
* 温度反馈  
* 环境表现  
* 与其他极端条件形成组合  
* 让世界看起来更加连贯  
  
## 9. 火源  
靠近：  
* 营火  
* 火焰  
* 岩浆  
* 其他高温方块  
时可以获得不同程度的局部升温。  
例如：  
```
营火
→ 小范围温暖

火焰
→ 较明显升温

岩浆
→ 大范围强升温
```
但这些主要影响温度读数。  
  
## 10. 天气  
天气可以对基础温度产生轻微修正。  
例如：  
## 下雨  
```
轻微降温
```
## 下雪  
```
明显降温
```
## 雷暴  
```
轻微降温
+
可与红石机械系统产生其他互动
```
天气温度修正不应该大到完全覆盖生物群系特征。  
  
## 11. 昼夜变化  
第一版可以暂时不做复杂昼夜温差。  
后续如果加入，也应保持轻量。  
例如：  
```
白天
→ 稍暖

夜晚
→ 稍冷
```
这种变化主要增加氛围，而不是增加生存压力。  
  
## 12. 温度对人物状态的总体原则  
绝大多数温度变化：  
**不直接影响人物状态。**  
例如：  
```
沙漠
→ 很热
→ 不扣血

雪原
→ 很冷
→ 不自动冻伤

水里
→ 降温
→ 不自动失温

岩浆旁
→ 升温
→ 不额外热伤害
```
这是一条核心规则。  
  
## 13. 温度反馈  
普通环境温度主要通过反馈表达。  
建议包括：  
* HUD 温度指示  
* 轻微色温变化  
* 寒冷环境可见呼气  
* 高温环境轻微热浪  
* 低温时屏幕色调稍冷  
* 高温时色调稍暖  
这些效果必须轻量。  
不能影响：  
* 瞄准  
* 建造  
* 阅读环境  
* 正常探索  
  
## 14. HUD 设计  
温度 HUD 不应该长期占据大量屏幕空间。  
推荐：  
```
冷
❄
```
或：  
```
偏热
☀
```
这种简洁提示。  
也可以使用：  
```
冷 ←────●────→ 热
```
形式的小型温度指示器。  
第一版以：  
**易懂、低干扰**  
为目标。  
  
## 15. 极端环境机制  
真正影响人物状态的情况应该非常少。  
优先原则：  
尽量使用 Minecraft 原版已有危险机制，而不是重新发明一套。  
最重要的例子就是：  
**细雪。**  
  
## 16. 细雪冻结  
Minecraft 原版已经存在：  
```
进入细雪
↓
冻结值上升
↓
屏幕结霜
↓
受到冻结伤害
```
Wildcraft 保留这套机制。  
不替换。  
不重复。  
  
## 17. 料理与细雪  
Wildcraft 的料理系统可以辅助玩家应对细雪冻结。  
例如：  
## 保暖料理  
可以提供：  
* 降低冻结累积速度  
* 延长进入冻伤阶段的时间  
* 加快离开细雪后的冻结恢复  
* 减轻部分冻结影响  
具体效果强度后续平衡。  
  
## 18. 料理不是免疫  
保暖料理不应该：  
让玩家完全无视细雪。  
即使吃了保暖料理：  
玩家长时间停留在细雪中仍然应该受到危险。  
料理的作用是：  
**提高容错和探索能力。**  
不是删除原版危险。  
  
## 19. 料理系统定位  
因此温度料理可以分为两类。  
## 普通环境适应料理  
作用：  
* 改善冷热环境反馈  
* 提高舒适度  
* 减轻部分温度视觉效果  
* 提升极端环境恢复能力  
  
## 极端环境辅助料理  
例如：  
**保暖料理**  
主要作用于：  
* 细雪冻结  
* 极端低温相关机制  
未来如果出现合理的原版或 Wildcraft 高温危险，也可以加入耐热辅助料理。  
  
## 20. 不设计“万能抗寒”  
抗寒效果不应该变成：  
```
喝了抗寒
↓
所有寒冷机制完全失效
```
更合理的是：  
```
普通寒冷
→ 更舒适

细雪冻结
→ 更慢

严重暴露
→ 仍然有危险
```
  
## 21. 耐热设计  
耐热料理同样采用弱干预。  
它不应该让玩家：  
* 站在火里  
* 泡在岩浆里  
* 完全免疫燃烧  
耐热主要作用于：  
* 环境表现  
* 高温区域舒适度  
* 特殊机械高温环境  
* 未来少量合理的高温机制  
  
## 22. 水与温度互动  
水的主要作用是：  
**快速降低当前环境温度。**  
例如：  
```
沙漠
↓
当前温度偏高

跳进水里
↓
温度快速下降
```
但这主要是环境反馈。  
玩家不会因为泡水自动获得“低温 Debuff”。  
  
## 23. 岩浆与温度互动  
同样：  
```
靠近岩浆
↓
当前温度快速升高
```
但玩家受到的真正危险仍然来自：  
**原版岩浆和燃烧机制。**  
  
## 24. 生物群系温度的重要意义  
生物群系温度主要服务于：  
* 环境沉浸  
* 料理系统  
* 探索准备  
* HUD 反馈  
* 天气表现  
* 少量极端环境机制  
而不是：  
**区域准入限制。**  
  
## 25. 探索设计  
玩家进入雪原时，不应该觉得：  
“没有抗寒料理就不能来。”  
而应该觉得：  
“这里很冷，如果我要去细雪区域，准备保暖料理会更安全。”  
同理：  
进入沙漠：  
“这里很热。”  
而不是：  
“我没有耐热 Buff，所以必须离开。”  
  
## 26. 与料理系统的关系  
料理系统负责提供：  
```
食材
↓
料理
↓
环境适应 Buff
↓
提升探索容错
```
料理是辅助。  
不是通行证。  
  
## 27. 与探索系统的关系  
温度应该增加：  
**区域差异感。**  
例如：  
```
雪山
→ 冷

沙漠
→ 热

海洋
→ 凉

岩浆洞穴
→ 热
```
玩家移动过程中可以明显感觉：  
世界环境正在变化。  
  
## 28. 与滑翔伞系统的关系  
高空区域可以根据所在生物群系或高度表现为：  
```
温度略低
```
但不建议第一版加入高空失温。  
滑翔伞本身不应该因为温度频繁受到惩罚。  
  
## 29. 与攀爬系统的关系  
温度默认不增加攀爬精力消耗。  
避免：  
```
雪山
→ 冷
→ 攀爬更累
→ 精力更少
→ 还要吃料理
```
造成多重惩罚。  
如果未来加入极端天气影响，也应保持非常克制。  
  
## 30. 与天气系统的关系  
天气可以改变温度。  
例如：  
```
雪原 + 下雪
→ 更冷

沙漠 + 夜晚
→ 稍微降温

雨林 + 下雨
→ 稍微降温
```
但这些变化主要作用于环境反馈。  
  
## 31. 与红石和机械系统的关系  
普通机械不会受到温度影响。  
第一版不设计：  
* 电池过热  
* 机械冻坏  
* 红石高温失效  
避免温度系统蔓延到所有玩法。  
如果未来确实需要特殊高温机械，也应作为单独设计。  
  
## 32. 温度变化速度  
玩家从一个环境进入另一个环境时：  
温度不应该瞬间跳变。  
建议：  
```
当前温度
↓
逐渐趋近目标环境温度
```
这样会更自然。  
例如：  
```
沙漠
→ 跳入水中
→ 温度逐渐下降
```
而不是瞬间从“炎热”变“寒冷”。  
  
## 33. 温度记忆  
玩家离开水、岩浆或火源后：  
局部修正逐渐消失。  
例如：  
```
离开水
↓
降温效果逐渐消退
↓
重新回到生物群系基础温度
```
这可以制造轻微的“余温”感。  
  
## 34. 第一版温度计算  
v0.1 建议只包含：  
```
生物群系基础温度
+
天气修正
+
水中降温
+
岩浆附近升温
+
火源附近升温
```
暂时不做：  
* 湿度  
* 风寒  
* 装备保暖值  
* 复杂海拔温差  
* 真实体温模型  
* 饮水需求  
* 中暑  
* 低温疲劳  
* 大量温度 Debuff  
  
## 35. 第一版实际影响  
v0.1 中：  
普通温度只影响：  
* HUD  
* 视觉  
* 环境表现  
* 料理信息  
真正影响生命值的低温机制：  
**继续使用原版细雪冻结。**  
Wildcraft 只对它提供料理辅助。  
  
## 36. 温度数值与状态分离  
需要区分：  
```
环境温度
```
和：  
```
玩家状态
```
环境温度可以很高或很低。  
但不代表玩家一定受到负面状态。  
例如：  
```
沙漠：高温
玩家：正常

岩浆旁：极高温
玩家：正常

雪原：低温
玩家：正常

细雪中：低温 + 原版冻结
玩家：危险
```
这是整个系统最重要的逻辑之一。  
  
## 37. 开发优先级  
建议开发顺序：  
```
① 读取生物群系温度
↓
② 当前环境温度数据
↓
③ 水与岩浆修正
↓
④ 天气修正
↓
⑤ HUD 显示
↓
⑥ 视觉反馈
↓
⑦ 料理 Buff 接入
↓
⑧ 细雪冻结联动
```
  
## 38. 第一版验收标准  
温度系统 v0.1 完成时，应满足：  
1. 不同生物群系拥有不同温度  
2. 温度变化连续而非瞬间跳变  
3. 水中可以明显降温  
4. 岩浆和火源附近可以升温  
5. 天气可以轻微改变温度  
6. 温度拥有清晰但低干扰的 HUD  
7. 普通冷热环境不会直接伤害玩家  
8. 原版细雪冻结保持正常  
9. 保暖料理可以辅助对抗细雪冻结  
10. 温度系统不会强迫玩家频繁管理状态  
  
## 39. 明确不做  
第一阶段明确不加入：  
* 真实体温模拟  
* 饮水系统  
* 中暑  
* 普通寒冷自动扣血  
* 普通炎热自动扣血  
* 寒冷导致移速下降  
* 炎热导致精力下降  
* 强制服装保暖  
* 机械过热  
* 电池低温衰减  
* 湿度模拟  
* 风寒公式  
* 大量硬核生存状态  
  
## 40. 最终设计定义  
Wildcraft 的温度系统可以定义为：  
以 Minecraft 生物群系为基础，根据天气、水、岩浆和局部热源动态计算环境温度，并主要通过 HUD 和视觉反馈强化世界环境差异。普通冷热环境不直接惩罚玩家，真正的极端生存危险优先沿用 Minecraft 原版机制，例如细雪冻结；Wildcraft 的料理系统则作为辅助工具，提高玩家应对这些环境危险时的容错与探索能力。  
它的核心目的不是：  
**逼玩家管理体温。**  
而是：  
**让 Minecraft 世界真正拥有“冷热变化”的感觉，同时保持原版自由探索的设计理念。**
