## Wildcraft 背负装备显示系统设计文档 v0.1  
## 1. 功能定位  
“背负装备显示系统”用于让玩家未手持的武器、盾牌和弓等装备，以可见模型的形式显示在人物背后或腰侧。  
目标体验类似《塞尔达传说：旷野之息 / 王国之泪》中角色装备常驻身体上的表现，但需要重新适配 Minecraft Java 版的人物模型、第一人称习惯、第三人称观察方式以及鞘翅、披风等原版内容。  
该系统主要属于：  
**角色表现层 / 装备视觉层**  
它不改变原版物品栏容量，不新增额外真实装备栏，不改变武器本身的功能。  
  
## 2. 核心目标  
系统需要实现以下体验：  
* 玩家携带的主要装备具有“真实挂在身上”的感觉  
* 第三人称下角色轮廓更加丰富  
* 其他玩家能够看到角色正在携带的装备  
* 当前手持装备与背负装备自然切换  
* 与 Wildcraft 的 Fuse 系统兼容  
* 尽量不破坏原版 Minecraft 的物品栏逻辑  
  
## 3. 核心设计原则  
## 3.1 不把整个背包都挂在身上  
系统不能读取玩家背包中的所有武器并全部显示。  
否则会造成：  
* 模型过密  
* 严重穿模  
* 视觉混乱  
* 性能浪费  
因此只显示有限数量的“代表性装备”。  
  
## 3.2 不新增真实物品容量  
背负槽只是视觉记录。  
例如：  
```
近战槽：下界合金剑
盾牌槽：盾牌
弓槽：弓
```
这些槽位并不额外存储物品。  
真正物品仍然存在于：  
* 主手  
* 副手  
* 快捷栏  
* 背包  
系统只记录：  
哪件装备应该被显示在角色身上。  
  
## 3.3 当前手持装备不能重复显示  
如果玩家当前手持某件装备：  
```
主手：钻石剑
```
则：  
```
背后：不再显示钻石剑
```
避免出现：  
手里一把剑，背后又挂着同一把剑。  
  
## 4. 背负槽结构  
第一版设置三个逻辑视觉槽。  
```
近战武器槽
盾牌槽
弓槽
```
分别记录：  
* 最近使用的近战武器  
* 最近使用的盾牌  
* 最近使用的弓类装备  
  
## 5. 自动登记逻辑  
系统优先采用自动登记，而不是要求玩家打开额外 UI。  
例如：  
```
玩家第一次使用钻石剑
↓
近战武器槽 = 钻石剑
```
之后切换到弓：  
```
手持：弓

背后：
钻石剑
盾牌
```
如果后来使用下界合金剑：  
```
近战武器槽
钻石剑
↓
下界合金剑
```
原来的钻石剑不再作为默认背负武器显示。  
  
## 6. 分类规则  
第一版建议至少识别以下类型：  
## 近战武器  
* 剑  
* 斧  
* 后续 Wildcraft 自定义近战武器  
* Fuse 后生成的近战装备  
## 盾牌  
* 原版盾牌  
* 后续自定义盾牌  
* Fuse 盾牌  
## 弓类  
* 弓  
* 弩  
* 后续自定义远程武器  
  
## 7. 默认背负位置  
角色模型背部需要预留多个视觉区域。  
建议默认布局：  
```
       弓
      ╲
       ╲
   [玩家背部]
      ╱
     ╱
  近战武器

   [盾牌]
```
实际位置建议如下：  
## 近战武器  
默认：  
**斜跨背部。**  
剑柄靠近肩部。  
剑身延伸至另一侧腰部附近。  
  
## 弓  
与近战武器使用相反方向斜跨。  
避免和剑完全重叠。  
  
## 盾牌  
贴近背部中央。  
整体略微偏左或偏右，避免覆盖全部武器。  
  
## 8. 不同武器类型姿势  
后续版本应根据武器形态调整背负角度。  
## 剑  
斜跨背部。  
  
## 斧  
斧柄斜跨。  
斧头部分位于肩部附近。  
  
## 长柄武器  
更接近竖直方向。  
减少横向占用。  
  
## 弓  
沿背部斜向悬挂。  
  
## 弩  
可采用更贴近背部的横向或斜向姿势。  
  
## 盾牌  
贴背放置。  
  
## 9. 当前手持与背负切换  
当玩家将背负装备切换到主手时：  
```
背后装备
↓
隐藏
↓
手持显示
```
当玩家切走时：  
```
手持装备
↓
重新显示到背部
```
第一版可以瞬间切换。  
后续版本再增加拔出和收回动画。  
  
## 10. 第一人称表现  
第一人称视角下：  
**不需要渲染玩家自己背后的装备。**  
理由：  
* 玩家本身看不到背部  
* 减少无意义渲染  
* 避免特殊视角穿模  
* 保持第一人称清爽  
第一人称依然正常显示：  
* 主手装备  
* 副手装备  
背负装备主要服务于：  
* 第三人称  
* 其他玩家观察  
* F5  
* 截图  
* 多人环境  
  
## 11. 第三人称表现  
第三人称是该系统最重要的表现方式。  
玩家需要能够清楚看到：  
* 背后的盾牌  
* 近战武器  
* 弓类  
* 当前手持装备  
角色轮廓应该清晰。  
装备之间不能完全叠在一起。  
  
## 12. 多人同步  
其他玩家必须能够正确看到该玩家当前登记的背负装备。  
因此服务器需要同步：  
```
近战武器槽
盾牌槽
弓槽
```
但只同步必要的物品信息。  
客户端负责实际渲染。  
目标：  
玩家 A 能看到玩家 B 背后挂着什么装备。  
  
## 13. 鞘翅冲突规则  
鞘翅占据整个背部，是该系统最大的视觉冲突之一。  
建议优先级：  
```
鞘翅
>
背负盾牌
>
弓
```
穿戴鞘翅时：  
## 隐藏  
* 背负盾牌  
* 大型弓类  
## 调整  
* 近战武器移动到腰侧  
例如：  
```
正常状态
↓
背后：剑 + 盾 + 弓

装备鞘翅
↓
背后：鞘翅
腰侧：近战武器
盾牌：隐藏
弓：隐藏
```
  
## 14. 腰侧武器  
腰侧可以作为备用显示区域。  
主要用于：  
* 穿戴鞘翅时  
* 背部装备过多时  
* 某些短武器  
例如：  
```
短剑
匕首
短斧
```
可以更适合腰侧。  
  
## 15. 披风兼容  
披风需要与背负装备共存。  
第一版优先保证：  
* 不崩溃  
* 不严重穿模  
* 背负装备正常可见  
视觉处理可采用：  
## 方案 A  
装备显示在披风外侧。  
## 方案 B  
部分大型装备存在时降低披风优先级。  
最终效果需要实际测试决定。  
  
## 16. 盔甲兼容  
背负装备的位置必须适配：  
* 无盔甲  
* 普通盔甲  
* 自定义盔甲  
不能仅按裸玩家模型的位置设计。  
建议附着位置相对于：  
**玩家骨骼 / 身体模型**  
而不是绝对世界坐标。  
  
## 17. Fuse 系统兼容  
这是重要要求。  
背负装备系统不能写死：  
```
钻石剑模型
铁剑模型
木剑模型
```
而应该尽量直接读取：  
```
ItemStack
```
并使用该物品当前的：  
* 模型  
* 贴图  
* 自定义组件  
* Fuse 数据  
* 特殊视觉属性  
进行渲染。  
这样：  
```
普通铁剑
+
烈焰材料
↓
Fuse 火焰剑
```
背在身后时仍然显示：  
* Fuse 后外观  
* 对应模型  
* 对应贴图  
  
## 18. 任意物品 Fuse 的适配  
如果后续支持更自由的 Fuse：  
背负装备显示系统应该尽量成为通用渲染层。  
逻辑：  
```
读取当前 ItemStack
↓
读取模型状态
↓
应用 Fuse 视觉信息
↓
挂载到玩家身体
```
这样无需为每一种组合单独编写背负模型。  
  
## 19. 特殊模型  
部分物品可能不是标准 Minecraft 手持模型。  
例如：  
* 大剑  
* 长枪  
* 巨型盾牌  
* 特殊弓  
* 古代武器  
这些装备可以提供额外配置：  
```
back_position
back_rotation
back_scale
```
用于定义：  
* 背负位置  
* 旋转角度  
* 缩放比例  
  
## 20. 装备位置配置  
后续可以为物品增加视觉标签或配置。  
例如：  
```
BACK_SWORD
BACK_BOW
BACK_SHIELD
WAIST_LEFT
WAIST_RIGHT
BACK_VERTICAL
```
系统根据类型选择对应挂载位置。  
  
## 21. 动画系统  
第一版不强制要求动画。  
## v0.1  
允许：  
```
装备瞬间从背部消失
↓
出现在手中
```
保证功能稳定。  
  
## 22. 拔出动画  
后续版本加入短动画。  
建议时长：  
```
0.15 ～ 0.25 秒
```
例如：  
```
手臂伸向背部
↓
武器从背部离开
↓
进入手持状态
```
  
## 23. 收回动画  
反向流程：  
```
手持武器
↓
角色做收回动作
↓
装备回到背负位置
```
动画不能明显拖慢玩家切换快捷栏。  
因此视觉动画与实际装备切换逻辑可以分离。  
即：  
游戏逻辑立即完成切换，动画只是表现。  
  
## 24. 动画优先级  
如果玩家正在：  
* 攻击  
* 拉弓  
* 攀爬  
* 滑翔  
* 使用林克时间  
装备收取动画不能抢占更重要的角色动作。  
建议动作优先级：  
```
战斗动作
>
移动特殊动作
>
装备切换动画
>
待机动画
```
  
## 25. 滑翔伞兼容  
玩家使用滑翔伞时：  
背负装备保持可见，但需要避免和滑翔伞模型冲突。  
可以根据滑翔伞结构调整：  
* 弓位置  
* 盾牌位置  
* 近战武器位置  
必要时可暂时隐藏部分大型装备。  
  
## 26. 林克时间兼容  
玩家空中拉弓进入林克时间时：  
弓本身处于玩家手中。  
因此：  
```
背部弓
→ 隐藏
```
其他装备：  
* 剑  
* 盾牌  
保持在背后。  
第三人称下可以形成非常清晰的角色轮廓。  
  
## 27. 装备视觉优先级  
为了避免角色背部过度拥挤，建议设置视觉优先级。  
```
当前手持装备
>
鞘翅
>
近战武器
>
盾牌
>
弓
>
其他装饰
```
当空间不足或模型冲突严重时：  
优先隐藏低优先级装备。  
  
## 28. 性能原则  
该系统主要增加额外物品渲染。  
必须避免：  
* 每帧扫描整个背包  
* 每帧重新判断所有物品  
* 每帧生成新模型数据  
应缓存：  
```
当前视觉槽状态
```
只有当：  
* 玩家切换装备  
* 物品发生变化  
* Fuse 状态变化  
* 装备鞘翅  
* 进入不同状态  
时才更新。  
  
## 29. 玩家数据  
需要保存的数据非常少。  
例如：  
```
lastMeleeItem
lastShieldItem
lastBowItem
```
但应尽量避免永久复制整个 ItemStack。  
优先保存：  
* 对应物品引用  
* 槽位信息  
* 必要组件数据  
具体方式在开发阶段决定。  
  
## 30. 第一版功能范围  
## Wildcraft 背负装备系统 v0.1  
必须实现：  
1. 识别剑类  
2. 识别斧类  
3. 识别盾牌  
4. 识别弓  
5. 识别弩  
6. 自动记录最近使用装备  
7. 三个视觉槽  
8. 当前手持装备不重复显示  
9. 第三人称正确渲染  
10. 其他玩家可见  
11. 基础背部位置  
12. 基础多人同步  
第一版不要求：  
* 拔出动画  
* 收回动画  
* 超精细武器分类  
* 完整披风处理  
* 完整鞘翅姿势  
* 所有 Mod 装备兼容  
  
## 31. v0.2  
增加：  
* 不同武器类型不同挂载位置  
* 鞘翅冲突处理  
* 腰侧武器  
* 披风兼容  
* Fuse 外观完整兼容  
* 自定义武器配置  
  
## 32. v0.3  
增加：  
* 拔出动画  
* 收回动画  
* 更自然的武器位置过渡  
* 滑翔伞状态适配  
* 林克时间第三人称动画适配  
  
## 33. 设计边界  
该系统明确不做：  
* 真实新增装备栏容量  
* 整个物品栏全部可视化  
* 背包系统重构  
* 武器重量系统  
* 武器自动切换  
* 基于背负位置改变战斗属性  
背负装备主要属于：  
**视觉表现系统。**  
  
## 34. 与 Wildcraft 核心设计的关系  
该系统不会独立创造新的玩法循环。  
它主要服务于：  
```
装备
↓
Fuse
↓
角色外观
↓
第三人称表现
```
同时增强：  
* 林克时间  
* 滑翔伞  
* 攀爬  
* 机械探索  
这些动作状态下的人物视觉完整度。  
  
## 35. 最终设计定义  
Wildcraft 的背负装备显示系统可以定义为：  
根据玩家最近实际使用的装备，在不改变原版物品栏容量的前提下，将未手持的主要近战武器、盾牌与弓类装备动态显示在玩家背部或腰侧，并根据手持状态、鞘翅、Fuse 外观以及第三人称状态实时调整其视觉表现。  
它的核心目的不是增加新的装备管理系统。  
而是让 Minecraft 中原本只存在于快捷栏和背包里的装备：  
**真正成为玩家角色外观的一部分。**
