# P3 滑翔伞验收记录

日期：2026-10-02（Asia/Shanghai）。版本 `0.1.0-dev.4`，本轮实现 P3 滑翔伞，并按用户决定加入独立装备位和双手收起规则。

## 环境与依赖

沿用 Apple M4 / arm64、macOS 27.0.1、JDK 25.0.4.1、Minecraft 26.3、Fabric Loader 0.19.5、Fabric API 0.161.0+26.3、Loom 1.18.2 和 Gradle Wrapper 9.7.1。没有新增生产依赖，没有迁移个人世界。P1 精力保存字段和格式 1 保持不变，新增的装备附件独立使用格式 1。

核对了 Fabric 官方 [物品注册](https://docs.fabricmc.net/develop/items/first-item) 与 [网络通信](https://docs.fabricmc.net/develop/networking) 文档。官方页面当前标注 26.2，原版菜单、创造编辑包、玩家模型、渲染状态及 Fabric 渲染层接口通过项目锁定的 26.3 游戏与 API 源码确认，并用实际编译和客户端检查验证。

## P3 服务端验证范围

6 项新的 GameTest 覆盖：

1. 专用槽仅允许滑翔伞、容量为一；Shift 装备与取出不重复物品；实际原版合成配方识别 3 皮革和 4 木棍，产出一把伞。
2. 普通背包中的伞不能开伞；重复 100 次输入不会重复收费，每刻费用只执行一次；开伞清理攀爬；双手真实物品保留；换快捷栏或移除装备结束滑翔。
3. 伤害、耗尽、地面和落地状态处理；继续心跳不能恢复被中断的开伞；创造飞行权限和原版鞘翅保留自己的操作。
4. 正常位移与越界位移限制；原版玩家保存/加载保留完整装备和精力，不保存开伞会话；方向速度有上限，不能产生升力。
5. 无心跳输入超过 20 刻后自动收伞。检查等待 23 刻，使用 40 刻测试时限。
6. 满背包取出失败时保留装备；重复死亡通知也只掉落一把伞。

## 实际客户端验证范围

完整流程通过真实游戏窗口、原版菜单和按键操作检查：

- 生存物品栏通过原版快捷移动包装备专用槽，服务端确认装备；创造模式个人装备页实际装卸该槽，位置不与原版槽重叠。错误物品、数量大于一及生存伪造创造编辑包被拒绝。
- 普通背包中的伞不能使用；装备后从地面持续按住跳跃不会自动开伞，必须在空中重新按下跳跃键。再次按下收伞，恢复原版重力。
- W 前进、A 侧移和固定缓降；第一人称提取的手持渲染状态为空，第三人称双手抬起抓伞。真实剑、盾和物品组件留在原格子中。
- 切换到弓、使用物品、攻击、交换副手和丢物品都会收伞，再执行原版动作。
- 开伞落地没有摔落伤害；实际伤害立即中断；耗尽后恢复下落。验证过程中使用传送准备起点，滑翔过程由按键、原版碰撞预测和移动包完成。
- 从 G 键抓墙转为空中跳跃开伞，服务端仅有一种移动状态，不同时扣攀爬与滑翔费用。
- 开伞切维度关闭状态并保留装备；保留物品死亡和复活保留伞；普通死亡只掉落一次；开伞时关闭并重开世界，装备保留，开伞状态不恢复。
- 回环 TCP 的 DedicatedServer 对象设置 `allow-flight=false`。真实前进 90 刻后仍处于滑翔，客户端与服务端高度差小于 0.3 格，服务端精力实际扣除；滑翔时断线再连接保留装备，不恢复开伞。

中英文 HUD 与独立装备位的实际画面另存为截图。附近玩家的外观使用跟踪范围内的状态同步，但本轮没有把单客户端 TCP 检查称为两台电脑或两个图形客户端的多人验证。

## 验证中的修正

- 新版本原版菜单使用 `ContainerInput` 与 `handleContainerInput`；按锁定源码修正测试入口，避免沿用旧名称。
- 创造界面父类字段不能作为该类自身的 Mixin Shadow 查找。客户端 Mixin 改为继承对应容器界面，实际加载、装卸和位置检查通过。
- 生存菜单的本地预测早于服务端包处理。测试等待完整服务端确认后才验证装备，避免把本地显示当作已收到的网络结果。
- 跨维度测试最初把玩家放入下界实心方块，导致受伤后正常拒绝开伞。测试改用清空的落点，保留受伤限制。
- 复活后原版尚未完成客户端加载确认时拒绝伤害。死亡掉落测试等待服务端加载确认后再执行第二次死亡，没有修改原版保护规则。

## 保存与边界

装备在 `wildcraft:glider_equipment` 中保存完整 ItemStack；P1 精力附件继续使用原格式。旧玩家默认空装备槽，开伞、输入与冷却不持久化。死亡先移除装备所有权，再生成一次掉落物；保留物品规则开启时保留。行为、数值和回退方式见 [P3-RULES.md](P3-RULES.md)。

本轮只使用此前授权的本机 EULA 测试目录和专用世界，没有使用个人启动器账号或个人存档。联机检查采用框架中的 DedicatedServer 对象；独立 SERVER 环境类加载另用新 Java 进程验证。独立服务端继续仅绑定 `127.0.0.1`，设置 `allow-flight=false`，复用 P1 专用验证世界，并实际响应控制台与保存退出。

伞的碰撞仍使用玩家身体，伞面没有单独实体碰撞；模型和每秒 4 点精力消耗属于开发参数。没有加入风、上升气流、雨天、伞升级或耐久。下一阶段是 P4 料理与温度，风与天气仍在 P10。

尚未覆盖：多客户端长期游玩、高延迟和丢包、其他装备或动画模组的兼容、Windows/Linux、个人账号实例及远程 CI。上游图形驱动、测试辅助方法弃用和离线测试鉴权提示会保留在日志中，成功不表示零警告。完整开发和成品客户端日志均没有 `moved wrongly` 或 `moved too quickly` 提示。
