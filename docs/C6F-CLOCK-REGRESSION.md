# C6F检查中发现的实际时间回归

2026-10-12，目标为保留C6D真实时间取收，不放宽原1.2秒端到端验收。

## 原始失败

7类盾兼容回归在EquipmentClientTest的5TPS测试失败，原始日志/tmp/wildcraft-shield-rig-regression.log。分离检查三种可证伪假设：归属同步等待、实际更新较慢时丢时间、上一场景残留。

新建独立测试世界的EquipmentClockClientTest，在正常与10FPS限制下真实切换携带槽并读取实际归属/取收；只将之前使用记录作为显式夹具，完整EquipmentClientTest仍保留实际攻击/举盾/拉弓登记检查。它测量归属收到、开始看到取收、完成；.34秒动作的实际时长上限.55包含10FPS帧量化。首次观察可能在动作已进行之后，补回首次真实progress对应的.34秒份额；这不改变动作定义，也不放宽原端到端1.2秒。

## 证据与根因

修正前新世界复现（/tmp/wildcraft-equipment-clock-repro-v2.log）：归属同步约.39754秒，首次观察后动画又用了1.00129秒，总1.39883秒，测试失败；当时实际测得12FPS。这排除了必须依赖前场景状态的解释，也表明同步本身不足以解释超时。

BackTransitions每次最多累加.05秒，较慢的实际更新把多出的有效时间丢弃，.34/.38秒取收被拉长。C6F新骨架复制了同种时钟限制，尚未发布，已同时修正。暂停仍由isPaused令delta为0；GUI/实际使用/运动互斥、断开与换世界仍按原有边界取消/重置。只改显示计时，不写玩家/库存/服务端数据。

移除每次更新的.05上限后，相同新世界测试通过，10FPS实际动画在.4–.5秒内（帧量化与观察包含在内）；归属约.4秒、完整切槽到完成约.8秒。最终原来的EquipmentClientTest（实际使用、暂停、5TPS、GUI、换装、备件）也通过，原1.2秒条件保持。临时DEBUG前缀已清理，保留C6 ACTUAL CLOCK作为回归测量日志。反馈循环保留为runEquipmentClockClientTest，不需生产插桩或依赖。

## 保留限制

这是显示时钟的修正，不承诺任意硬件/后台负载下都能在固定帧数呈现所有中间帧。C2旧方向平滑等其他时钟未在本次顺手重写。完整原场景与C6F相关回归、最终构建实际结果见C6F-SHIELD-RIG-VERIFICATION.md。
