## 原料单人闭环

`SurvivalClientTest`只提供16类原版原料、原版平台/墙/营火/工作台和20级经验样本。以下产品和交易由真实工作台、容器、输入或世界路径取得：

1. 原生16次合成取得伞、锅、空电池、充电器、主体、两风扇、两轮、弹簧、翼、弓、铁剑、两红石块及制造机。实际扣42铁/20铜/23红石，另用已提供桶/炉等；当前等级消费到0后历史峰值20、上限140保留。
2. 原生库存移动将伞放唯一装备槽；制作保暖II料理、食用返碗；真实G/W攀爬、跳跃开伞、切弓收伞、空中拉弓和一次放箭，恢复20TPS、箭4→3。
3. 实际副手石头/V融合铁剑、攻击目标、融合次数32→31；目标为测试生成的无AI生物。
4. 实际放置固定红石块与充电器，将新合成空电池充到1000；原生安装电池/风扇/双轮/翼、空手乘坐、R/W驾驶，再启停、拆卸和空主体攻击回收。
5. 实际放置制造机、投入4铜/2红石、原生按钮取得一次补给，铜余40、红石余39、铁余22、箭余3、碗2。世界磁盘保存重开，伞槽/峰值/主体和回收电池精确余量保留。

站点间通过测试传送定位；平台延长避免设备滑出场景，驾驶停用后清零测试主体速度再进行拆卸。不存在直接give Mod成品、设置免费电量或用恢复API代替原生拆卸。此场景未覆盖从零采矿、长程自然地形或人工操控手感。

## 弹簧配方问题的复现与修复

新增实际匹配检查先失败于`Native packaged output: spring`。旧图案` I ` / `IRI` / ` I `与原版指南针完全相同，实际结果为指南针；旧按ID直接取配方的检查没有测试工作台选择。这是已由资源图案和原生结果确认的原因。

改为`II ` / ` R ` / ` II`，保持4铁＋1红石；在原版匹配器和实际工作台均得到弹簧，旧图案明确断言得到指南针。失败日志保留为spring-conflict-before-fix.log，最终83项/21类结果另存，不能把失败日志当最终验收。
