# Wildcraft 开发路线

已确认：Minecraft Java Edition、Fabric、macOS 为主要开发与测试环境。

当前执行范围是 P0 工程骨架。具体系统边界、保存载体和资源流程见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 范围

1. 历史最高经验等级决定精力上限。
2. 攀爬和滑翔伞消耗精力。
3. 原版食材料理、温度、抗寒与耐热效果。
4. Fuse；任意物品作为融合材料保留为研究方向。
5. 红石控制、固定无限能源、充电器、有限电池。
6. 翼、风扇、火箭、电池、弹簧、轮子、稳定器、浮力装置。
7. 机械吸附、安装、拆卸与回收。
8. 古代装置制造机。
9. 风与天气对探索和机械的影响。

不纳入：究极手、时间倒流、大型 Boss、完整神庙、大型新维度、复杂剧情、大量新矿石/资源体系、小型世界事件、环境谜题、机械蓝图。超复杂机械物理暂缓。

## 工程原则

- 单一 Mod 项目，按玩法系统分包；客户端与公共代码分开。
- 服务端决定消耗、伤害、产出、存档和安装结果；客户端处理输入、预测、界面和渲染。
- 玩家进度使用持久化 Data Attachment；物品使用 Data Components；设备和移动机械随游戏对象保存。
- 死亡不降低历史等级；重连不能免费恢复精力或电量。
- 机械先采用一个主体、有限节点和部件功能的组合；复杂动态关节与任意方块实体移动另行研究。
- 红石控制信号与电量分开；无限能源必须固定在世界中，移动机械使用有限电池。
- 未知 Fuse 材料的读取、效果推断、数据保存和外观分别验证。
- 不因里程碑名称增加确认关卡；按用户授权范围执行。生产依赖、发布等操作遵守已有批准规则。

## 开发阶段

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| P0 | 项目、测试物品、构建和运行说明 | 客户端、独立服务端、独立成品实例加载通过 |
| R0 | 移动机械、节点、复杂组件与任意 Fuse 的隔离实验 | 记录可行范围与失败边界，确定正式方案 |
| P1 | 玩家数据、历史等级、精力计算与 HUD | 升级、降级、死亡、重连与两玩家隔离通过 |
| P2 | 攀爬与耗尽处理 | 墙角、顶部、障碍、受击和联机回弹验证 |
| P3 | 滑翔伞与精力消耗 | 开伞收伞、落地、耗尽、死亡和切维度验证 |
| P4 | 料理与温度 | 输入产出、效果叠加、环境适应与时长保存正确 |
| P5 | 红石能源、充电器与电池 | 电量守恒、输出速率、拆装和固定能源限制正确 |
| P6 | 机械主体、节点、风扇、电池、拆卸回收 | 完成组装、运行、停止、拆卸、再安装；无重复物品 |
| P7 | 翼、火箭、弹簧、轮子、稳定器、浮力装置 | 单部件与组合行为一致，区块重载保持状态 |
| P8 | 古代装置制造机 | 输入和输出各执行一次；中断恢复；不通过重开界面重抽 |
| P9 | 正式 Fuse 与宿主适配 | 效果、耐久、附魔、维修、保存与联机一致 |
| P10 | 风与天气互动 | 客户端结果一致，强度可控，存档加载不突变 |
| P11 | 平衡、性能、兼容和发行准备 | 全流程生存与多人测试、存档升级、长时间运行通过 |

P0 是工程可运行版本；P3 是首个探索可玩版本；完成 P11 后才形成当前完整范围的正式候选版。

## 从空项目开始的第一批任务

1. 核实游戏与 Fabric 的稳定组合，固定 Wrapper、Loader、API 和 Loom。
2. 安装 JDK 25 与 Java IDE；确认终端、构建和 IDE 可使用同一 JDK。
3. 建立本地 Git 项目、公共/客户端来源分离和资源目录。
4. 注册 `wildcraft:test_core`，放入创造分类；制作原创占位贴图。
5. 生成物品模型、显示定义和中英名称，检查资源路径。
6. 构建 JAR，检查元数据、资源和测试代码隔离。
7. 实际启动客户端，创建世界、发放物品、查看贴图、保存并重新进入。
8. 连接本机测试服务端，检查注册表与物品同步。
9. 在接受 Minecraft EULA 后，用成品 JAR 启动独立服务端，确认响应和保存退出。
10. 用成品 JAR 重跑客户端验证，整理说明、日志、截图、源码与版本标签。

这些任务的真实执行状态见 [VERIFICATION.md](VERIFICATION.md)。P0 不添加精力、攀爬、料理、Fuse 或机械行为。

## 各阶段的关键边界

| 阶段 | 必须覆盖的边界 |
| --- | --- |
| R0 | 移动主体跨区块、玩家乘坐与碰撞；有限节点；复杂材料组件的体积、编码、模型回退和缺失依赖 |
| P1 | 消费经验不减峰值；命令改等级；死亡、切维度、重连和两玩家隔离；精力数值有上下限 |
| P2 | 内外墙角、墙顶、障碍、半砖、无可攀表面、受击、耗尽和延迟纠正 |
| P3 | 装备条件、开收伞、地面误触、耗尽下落、受击、切维度和与原版飞行冲突 |
| P4 | 无效食材、重复投入、满库存、效果叠加、区域温度、装备抗性、时长保存与下线处理 |
| P5 | 零电量、满电、速率限制、串联转移、拆分堆叠、区块卸载；红石强度不能直接成为无限电池 |
| P6 | 节点占用、距离和容量、满库存回收、同时安装、死亡、卸载、重载和部件只消费一次 |
| P7 | 各部件能源开销与停止条件；轮子地面判定、稳定器限制、浮力介质；有限组合的碰撞和乘坐 |
| P8 | 投入与输出各一次；重启、中断、重开界面和满库存；产出不能被重新抽取 |
| P9 | 已支持宿主、未知材料、附魔与耐久、维修与拆除规则、跨容器保存和动态模型回退 |
| P10 | 服务端风场一致；攀爬、滑翔、翼和风扇受到受控影响；雷雨与能源交互不产生无限输出 |
| P11 | 完整生存流程、多人竞争与延迟、长期运行、性能负载、升级备份与兼容回归 |

R0 的实验不会自动成为正式功能；将可行性、限制和需要新增依赖的部分写成结论。正式系统仍按阶段验收，超复杂机械物理保持暂缓。

## 尚待各阶段确定

- 精力的成长曲线、消耗与恢复数值。
- 死亡时当前精力的初始化规则；历史峰值长期保留。
- 攀爬表面、操作方式和天气影响。
- 料理操作界面与效果叠加规则。
- 机械尺寸、部件数量、结构支持范围与安装工具。
- 火箭是否一次性消耗；浮力装置的作用介质。
- 制造机投入物、产出池与权重。
- Fuse 拆除与回收规则、未知材料效果与支持边界。

## 验证与版本

规则计算与编码使用相关单元测试；库存、实体与方块行为使用 GameTest；移动手感、模型与联机使用实际客户端验证。每阶段覆盖死亡、重连、切维度、重启、区块重载、满库存与多人同时操作等相关边界。

`main` 保持可构建。功能分支短期存在；风险研究用 `spike/`，游戏升级单独成分支。Mod 版本、Minecraft 版本与存档格式版本分别管理。

升级保留旧数据读取并准备世界备份。回退存档版本时恢复对应备份，不只更换旧 JAR。

资源流程：占位模型验证 → 定稿尺寸与节点 → 正式美术 → 导出 → 游戏检查。资源生成与手写资源分开管理；保留原始模型与贴图。
