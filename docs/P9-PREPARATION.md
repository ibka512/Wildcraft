# P9 正式 Fuse 开发准备

2026-10-04，P8之后的执行顺序。用户授权按推荐路线连续开发，不新增生产依赖；任意物品仍为专项研究，不能把R0保存实验冒称正式战斗系统。

## 首先处理真实物品与保存

沿用原宿主ItemStack，添加独立格式1融合组件，不为每种组合注册新物品。材料只保存一件完整快照，附魔、名称、损伤、容器内容不写回宿主，不免费修复宿主。正常材料接受前先完成编码、大小与嵌套检查，再原子消费一件；重复提交、已有融合、宿主/材料同一对象、嵌套融合和超预算一律无副作用。

R0缺失物品ID会导致ItemStack解码失败，正式底座先保存受限的原始标签快照；解码不可用时保留原始内容并禁用材料效果，不能偷偷替换成空物品或重新生成。读取返回副本，等同性和哈希按保存内容。上限沿用8192字节并在编码前后验证；第三方未知组件、递归容器、移除模组仍需独立报告。原玩家/装备/能源/机械格式保持不变，升级和回退使用世界副本。

## 实际执行顺序

1. 正式数据组件与无副作用验证器，测试普通材料、损伤命名工具、容器内容、未知ID降级、超预算与重复操作。这个切片尚无玩家入口，不能标为完成P9。
2. 明确宿主与材料支持表，再接真实融合/拆分交互：服务端只接受意图，重算两件当前真实物品；库存满不丢材料，拆分不复制，宿主与材料耐久保留。推荐专用融合操作，避免替换攻击、举盾和拉弓。
3. 按已支持材料分别实现武器/盾/箭效果、伤害和消耗，验证原版附魔、耐久、维修与宿主破坏；不把材料本身所有能力自动继承。
4. 在当前宿主模型上添加有界通用表现，独立验证手持、掉落、地面和背负。外观同步仅发送安全白名单，不传容器/私人组件；体积和通用回退与效果分开。
5. 原生客户端、保存重载、普通双客户端竞争操作、无测试Mod服务端与完整回归通过，才冻结新完整阶段。P9.1再核对空中箭一次效果、背负一致及料理/精力交互。

开始实现时核实固定26.3本地组件/网络/物品模型接口，保持src/main无客户端引用。剩余风与天气、多人局部林克时间仍在原路线，不以这个首切片缩减后续范围。
