# R0 技术验证结论

基线：Minecraft 26.3、Fabric API 0.161.0+26.3。实验属于独立 `wildcraft-test` 模组，代码在 `src/gametest/java/dev/wildcraft/test/research`，不打进游戏 JAR。

## 机械：采用单主体与有限安装节点

已经实际验证：

- 单个 Entity 主体可以通过原版移动与碰撞路径移动，并被墙体阻挡。
- 原版乘坐关系可以携带玩家；测试检查移动后的乘坐关系和位置。
- 四个实验节点安装一块电池和一个风扇；部件消费一次，占用节点和越界节点拒绝安装。
- 剩余电量保存在已安装的电池物品组件中；运行消耗电量，停止后不继续移动。
- 背包满时保持部件安装；腾出空位后回收，电量保留，再次回收拒绝。
- 实际客户端测试中主体跨越区块边界，随后关闭并重开世界；位置、电量和节点清单正确重载。

发现并处理：原版创造模式 `Inventory.add` 在背包满时可能丢弃输入并报告成功。回收必须先检查真实可用空间，再转移部件所有权。

可行性结论：正式 P6 沿用单主体、有限节点、服务端安装与回收的方向，当前不需要新增物理库。

限制：实验主体尺寸固定为 1.2 × 0.6，碰撞盒随世界坐标轴对齐；实验风扇提供固定水平位移，没有实现真实推力、扭矩、重心、轮胎接地或动态关节。四节点只是实验参数。实验使用无模型渲染器，完成的机械外观和多人乘坐手感属于后续阶段。不能由此推断任意形状、旋转碰撞或复杂车辆已经可用。

## Fuse：保存材料可行，效果和外观需要独立开发

使用一把原版铁剑，实际验证三类材料：

| 材料 | 保留内容 |
| --- | --- |
| 普通圆石 | 类型和单个材料数量 |
| 钻石镐 | 类型、损伤值、自定义名称 |
| 潜影盒 | 内部物品、内部工具损伤和嵌套组件 |

实验在检查成功后消费一个材料；重复融合拒绝，不再次消费。材料快照的访问返回副本，组件具有按内容比较的相等性。编码与解码后，宿主和材料的内容一致。

实际客户端把融合物品从玩家背包转入箱子，再转成掉落物；关闭并重开世界后仍可读取嵌套数据，拾取回背包一次。

实验将材料 JSON 编码限制在 8192 字节，超出限制时宿主和材料均不改变。缺失物品 ID 的原版解码会失败；正式版本必须设计保留原始信息或降级的策略，不能直接承诺移除其他模组后仍能恢复全部材料。

可行性结论：继续研究“任意已注册且数据可编码、大小受控的物品作为材料”。正式 Fuse 的宿主适配、属性推断和材料显示分别验收。

限制：这次没有增加攻击伤害、附魔行为、维修或拆除规则；也没有把材料模型拼到剑上。宿主使用原版外观。未知组件、深层嵌套、移除依赖后的恢复、其他模组属性及通用模型组合仍未解决。
