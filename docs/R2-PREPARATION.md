# R2 多人局部时间：研究入口

2026-10-04。P9已完成，P9.1组合与完整17类回归已通过。本阶段仅研究代码/专用世界，不直接开放正式多人技能；没有新增依赖或真实数据迁移。

## 固定26.3接口的实际发现

已读取本机固定版本的Minecraft公共sources JAR：ServerLevel.tickNonPassenger先commonTick、再tick，再处理乘客；tickPassenger也会单独处理Player。候选实体降频必须保护载具和乘客，不可只取消外层tick后让玩家一并停住。ServerEntity.sendChanges有独立trackingPosition/插值与同步间隔，服务端模拟降频不等于客户端投射物预测也降频。

Brain.tick的MemorySlot逐次tick，而行为启动/结束读取level.getGameTime。这意味着简单4次跳过3次会同时出现两类时钟：实体计数按5次/秒，世界时间仍20次/秒。需要测AI、免伤、燃烧、药水、重力、碰撞、抛射物以及追踪，而不能把移动变慢直接当完整局部时间。

## 研究顺序与通过门槛

1. 测试Mod独立服务器实体门控实验：一只Mob每4个世界刻执行1次完整commonTick/tick，对照Mob正常，世界仍20 TPS；停止门控后正常继续、不补跑、不保存门控。先测原生计数和恢复，不把这一项称为多人技能。
2. 两个普通客户端的真实场景：普通玩家、全局时间、红石/料理/机械保持正常；目标的服务端位置与两端各自画面一致，不读另一JVM状态充当网络证据。
3. 玩家/投射物归属与范围：保护所有玩家、载具/乘客、其他玩家射出的箭和现有机械。先实验非乘骑敌对Mob与其箭；两人作用集合重叠只采用一次最低速率，不能相乘、不争夺同一全局TickRate。范围进入/退出、死亡、落地、耗尽、换维度、离线和区块卸载撤销。
4. 原版伤害/附魔/Fuse一次结算、箭位置预测、药水/燃烧/AI计时、料理与精力有效时间；先排除不一致，再决定正式支持表。无法可靠解决的实体/能力具体列为限制，不能以滤镜代替实际局部时间。
5. 验证开销及实体数量上限，不强制加载区块；通过后再写P10.1正式合同。R2结论暂未通过时，风/天气P10可以继续独立开发；正式多人林克时间保持关闭。

第一项候选实验放src/gametest/research/localtime，不进入src/main。其门控只研究服务器端5/20节奏；尚不能承诺正确AI、客户端预测、PvP、公平性或正式技能。既有R1实验和单人FocusTime不复用共享静态客户端所有者作为多人状态。相关原生代码仅作为本机接口依据，不把游戏源码或缓存随项目交付。
