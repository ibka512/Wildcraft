## 三处应补充的制作说明

### F01-04：把status0写成明确的食材等待状态

当前清单写“匹配食材”。[CookingPotEntity.java](/Volumes/仕事/Wildcraft/开发环境/project/src/main/java/dev/wildcraft/cooking/CookingPotEntity.java:50)中，status0实际是未找到匹配配方，覆盖空输入、缺少食材或组合不匹配；语言中的“放入匹配食材”是操作提示。设计稿若把它理解成“配方已匹配并就绪”，会画错状态。

建议保留5张状态稿，并用以下对照：

| 状态值 | 实际含义 | 制作稿名称 |
| --- | --- | --- |
| 0 | recipe=null | 缺食材 / 未匹配配方 |
| 1 | 有配方、有碗，缺少有效热源 | 缺热源 |
| 2 | 正在推进烹饪 | 烹饪中 |
| 3 | 有配方但没有空碗 | 缺空碗 |
| 4 | 输出格已有成品，优先等待取走 | 成品待取 |

不新增状态或行为，只补明确的制图对照。

### F06-02：区分完成待提交与成品已入槽

[FabricatorEntity.java](/Volumes/仕事/Wildcraft/开发环境/project/src/main/java/dev/wildcraft/fabrication/FabricatorEntity.java:39)给出的5状态为：0材料就绪、1材料不足、2制造中、3任务已到100刻但输出格占用、4输出格已有已完成成品。当前清单的“完成/待取旧产出”容易把3和4混在一起。

建议五张稿明确命名：**可开始 / 材料不足 / 制造中 / 完成但输出位占用 / 成品已入槽待取**。状态3仍保存待提交结果，不能把尚未提交的随机结果提前画到界面；状态4则允许显示真实输出槽物品。两者都是现有状态，不需要增加菜单槽。

### F05-01：在设计稿上标出六节点与控制板命中范围

当前[MachineRenderer.java](/Volumes/仕事/Wildcraft/开发环境/project/src/client/java/dev/wildcraft/client/mechanics/MachineRenderer.java:37)绘制的控制板范围，比[MachineNodes.java](/Volumes/仕事/Wildcraft/开发环境/project/src/main/java/dev/wildcraft/mechanics/MachineNodes.java:22)接受的点击区更大。清单正确要求保留交互范围，但制作任务最好附上实际坐标，避免把整块可见板当作可操作区。

主体局部坐标，以方块为单位：

| 对象 | 坐标或范围 |
| --- | --- |
| 顶节点 | (0, .65, 0) |
| 底节点 | (0, 0, 0) |
| 后节点 | (0, .325, −.7) |
| 前节点 | (0, .325, .7) |
| 左节点 | (−.7, .325, 0) |
| 右节点 | (.7, .325, 0) |

正式外观应围绕现有节点/命中区出稿；扩大可见装饰不意味着扩大功能范围。此项只核对代码坐标，没有本轮实机点击验证。
