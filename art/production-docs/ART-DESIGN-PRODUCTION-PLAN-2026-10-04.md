# Wildcraft 下一批美术设计与制作流程

日期：2026-10-04。基线：本机 dev.14 / Minecraft 26.3 / Java Fabric，源码 a15536a。**本次交付规划；所有新制作任务尚未启动。**

依据：[原待制作清单](PENDING-ART-ASSETS-2026-10-04.md)、[逐项核对报告](PENDING-ART-ASSETS-AUDIT-2026-10-04.md)、[32项制作排队表](ART-DESIGN-PRODUCTION-SCHEDULE-2026-10-04.csv)。此前 dev.6 美术规划仅用作风格与流程参考，当前状态以 dev.14 核对结果为准。

## 1. 这一轮要达到的结果

把料理、能源、机械、制造机与 Fuse 的功能原型转为统一、可编辑、可接入的正式美术。首先保证玩家看得懂物件、安装方向和当前状态，再增加材料细节与轻量动态表现。

已接入的滑翔伞、精力 HUD、核心角色动作、背负与单人林克时间美术继续作为基准。保暖、耐热、精力恢复与满/空电量的10份已采用 PNG及10份 Aseprite源稿直接复用；不重新安排从零绘制。温度v2与 Fuse标记v1仍是待审稿，复核后才决定保留或修改。

本计划覆盖原清单全部32项：22项P0、7项P1、3项P2。批次表示设计依赖和制作顺序，不要求一次审完一整批。仍按此前节奏，每次交付一个资产或一个不可分的组件，用户采用后推进下一项；同一项中的像素修整、导出与文件检查连续完成，不增加例行确认关卡。

模型纹理尺寸依UV与近景验证决定，不要求实体纹理也做16/32双份。共享色阶不等于把木材、陶器、金属和汤面压成同一套少量颜色。

## 4. 统一视觉方向

- **形态**：符合Minecraft方块与低多边形比例。远处靠轮廓区分锅、电池、风扇与制造机，近处才读缝线、接点与刻痕。每件保留一个主要识别点，避免给所有装置堆同样的装饰圈。
- **生活物件**：锅与料理优先宽口、稳定底部、清楚的内外遮挡；食材颜色与器皿分离。七配方归四外观，I/II用文字或小标识，不新增不同级别的碗。所有料理使用与返还空碗相符的器皿，不引入新的盘子库存机制。
- **材料**：建议延续已采用伞的木/布语言；生活器具用受控的深色金属与木柄，能源/机械共用暗金属、铜接点、红石亮区。制造机以更清楚的入口/出口与框架区别于充电器。具体色阶在小样中校准，不把新建议伪装成已采用稿。
- **光照**：物品图沿用左上受光，安排亮、中、暗面和接缝遮挡。大色块应说明曲面与体积；不靠大面积同色或随机噪点制造“低像素”风格。
- **状态**：绿色有效、琥珀选中延续现状；不可安装/占用还需要轮廓或符号与短文字。停机、缺电、燃料耗尽、冷却不能仅用同一种灰色混写。
- **温度**：图标上暖下冷，七档为环境等级，不标摄氏度，不表现成必须管理的生命资源；保暖辅助细雪，耐热不暗示抗火。
- **角色比例**：手持与背负继续共用原版物件尺度，已有采用比例1.00作为基准；用挂点与旋转解决空间，不把盾、弓或武器大幅缩小来避穿插。

## 5. GPT、生图、Aseprite与模型工具的分工

GPT负责简报、参考筛选、概念提示、像素与几何修订、规格、文件校验、接入说明和审稿对照。用户负责视觉采用；普通执行细节由GPT连续完成。

### 5.1 2D图标

1. **读简报**：固定用途、真实显示位置、主轮廓、材料、光源、32/16身份一致性，以及不能改的玩法语义。优先引用已采用同类资产。
2. **定向概念**：生图提示从一开始就限制为目标像素预算与Minecraft阅读方式；必要时比较2–3个轮廓，不堆多张相近大图。生成图保留作概念原件。生图接口无法保证原生32×32/16×16网格或精确输出，不能用提示词或缩放冒充已经做好的原生像素稿。
3. **原生32制作**：Aseprite建立真实32画布，先做剪影和明暗结构，再整理材料色阶。缩放导入只能当草稿；保留概念对照，避免整图坐标重画时偷偷改变形态。
4. **原生16适配**：继承32的同一物件、主色、朝向与关键结构，在16画布重新组织轮廓与像素簇。删除读不出的细节，不直接自动缩小交付。32采用而16未通过时，保留32，只迭代16。
5. **自检和审稿**：原尺寸1×、2×、4×/8×最近邻、透明/深/浅背景和真实槽位模拟。先评识别、结构与体积，再检查尺寸、透明边缘、源稿/PNG一致；技术合格不能代替美术通过。
6. **版本与导出**：每次保留v01/v02等独立版本；已采用文件不覆盖。交付Aseprite、PNG、预览与用途说明。已采用效果图标在此直接做布局与必要适配，不重新生图。

制作阶段使用本机Aseprite Web完成真实画布、图层、像素修改与导出。操作前确认编辑器状态与像素哈希，保存后重新打开/核对；规划阶段不启动编辑器。来源流程：[既有像素工作流](/Volumes/仕事/开发/2026-10-02/referenced-chatgpt-conversation-this-is-an-2/outputs/art-prototypes/Wildcraft-像素美术工作流-v1.md)、imagegen与Aseprite Web技能的工具边界。

### 5.2 3D、UV与机械动态

1. 从代码提取单位、朝向、碰撞、挂点、轴心与真实动件，先写尺寸简报。
2. 生图可提供造型与叠放参考，重点看正面/侧面/底部结构；多视图生成不保证几何一致，最终尺寸以简报和实际模型为准。
3. 先做灰模，检查剪影、六节点、喷口/轴向、手持与背负空间，再分配UV。
4. 优先沿用项目已有方块模型与实体几何方式，交付可编辑几何源、分组层级、UV和导出映射。若使用模型编辑器，不把未验证能导出的网格文件当游戏成品，不为此新增生产依赖。
5. Aseprite制作UV像素材质。贴图密度按世界尺寸协调；尽量复用接头、螺栓、壳体与灯面材质区域，独特轮廓由几何承担。
6. 给动件写轴心、旋转方向、行程、状态驱动与停止姿态。风扇/轮子旋转、弹簧位移由程序驱动；灯与电量用状态/遮罩，不绘制整套逐帧图片。
7. 审稿同时给可读渲染与实际几何线框/尺度图。AI渲染只证明意图，不能证明UV正确、模型可加载或节点可点击。

### 5.3 UI、特效与声音

UI以现逻辑尺寸和槽位为固定底板，先摆真实图标再补背景、标题、提示。文字、等级、倒计时与数值保留程序绘制。交付静态皮肤/组件、布局坐标、状态映射；中文不用烘焙成背景。

特效先用原版精灵和程序参数测试语义，只有辨识不足才制作小型原创精灵。火焰方向与喷口一致；熄火不能残留持续尾焰；冰效果不能伪装成新增普通环境冻伤。

声音先列实际触发事件、去重与优先级，再制作短音。循环必须说明距离、同时播放数量、停机/拆卸/卸载时停止方式；多台设备不能叠成持续噪声。美术采用与最终混音验收分别记录。

## 7. 接入前必须明确的边界

- **料理**：七配方有4个kind，现只有一个meal图和物品模型。四外观需要后续客户端/资源生成按kind分流，不能仅改名为四个新物品。锅下使用原版有效火源，不增加一套燃料栏。
- **锅界面176×182**：3食材槽(26,33)/(46,33)/(66,33)，空碗(46,58)，成品(134,45)。库存行Y100/118/136，快捷栏158。五状态是缺食材或不匹配、缺热源、烹饪中、缺空碗、成品待取。不能把status0画成已经就绪。
- **温度/效果HUD**：心和精力下方排列；温度后接三类料理效果。检查多排心/吸收心、精力隐藏、中英文、小窗口与三效果同时存在。专注时避免与边缘色调抢读数；不增加全屏强滤镜。
- **电池/充电器**：容量1000；1个真实槽。界面176×166，电池(26,35)，库存Y84/102/120，快捷栏142。五状态：无电池、缺固定红石源、充电中、满电、等待共享供电。携带红石块不能画成无限随身电源。

## 10. 第一项：F01-01料理锅的可执行简报

**造型建议**：宽口深色金属锅，较稳的底部与明确锅沿厚度；把手可用木/金属分材质；局部铜接点仅在确有用途时保留。料理与蒸汽不能占掉主体轮廓。前沿遮挡锅内，锅壁有亮、中、暗面，不连续收成尖底。

**第一轮检查顺序**：无纹理灰模看剪影 → 标尺寸和碰撞 → 看内腔/把手/锅底 → UV及像素材质 → 放在原版火源上的展示 → 远景/近景/物品展示自检 → 用户审稿。生图渲染作为造型参考，实际几何图负责证明尺寸与结构。
