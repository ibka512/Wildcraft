# Wildcraft 下一阶段美术工作规划 v1

日期：2026-10-03。依据用户提供的 `ASSET-REDESIGN-PLAN.md`、`Wildcraft-美术资产清单.csv`、`Wildcraft-已完成阶段美术整理.zip`，以及本对话的资产采纳记录。

本计划建议先完善当前已实现的探索体验，再为后续料理、温度、Fuse 和机械系统制作正式资产。此次仅交付规划，没有生成新图、建模、改动画、修改游戏资源或执行游戏验证。原三份参考文件保持原样。

## 5. 第一版复用与暂缓边界

第一版继续复用：原版红心全状态、字体、按钮/常规槽框、快捷栏、经验条、食物条、剑斧盾弓弩、盔甲、玩家皮肤、雨雪/闪电、世界方块与环境；背负调用真实物品模型，保留染色、盾图案与附魔等表现。

暂缓：复杂伞布物理、复杂机械物理、精细手指模型、专用服装、剑鞘/箭袋/收纳伞包、整套原版 UI 重绘、大范围屏幕冷热滤镜、长篇角色动画与宣传美术。收放动画与设置页美化排在核心表现之后。

明确不安排资产：究极手、时间倒流、大型 Boss、完整神庙、新维度、复杂剧情、大量新矿石、小型世界事件、环境谜题、机械蓝图。不会以“美术需要”为理由反向新增这些玩法。

## 6. GPT 全流程与工具分工

| 步骤 | GPT 负责的工作 | 成果与验收边界 |
| --- | --- | --- |
| 需求与参考 | 根据源码、截图和已采用资产确定用途、比例、尺寸与必要状态 | 一页制作简报；先解决对象与用途，避免生成无接入位置的装饰图 |
| 设计出稿 | 对 2D 提供明确轮廓、材料和像素簇意图；对 3D 提供结构/三视图；对 HUD 提供状态布局 | 图像生成用于概念和风格验证；高分辨率“像素风”不是原生 32×32/16×16 成品 |
| 原生 2D 制作 | 由 Aseprite Web 完成原生画布、调色板、透明边缘、局部像素修订 | 分别检查 32 与 16；16 可删减细节，但伞面、框架等核心结构不能变成另一种物体；避免大片无层次同色 |
| 3D 制作规划 | GPT 负责几何、UV、材料分区与坐标/握点规格，使用适配的模型工具保存可编辑源文件 | Aseprite 负责纹理，不承担 3D 建模；PNG/三视图也不代替 `.bbmodel`；实际模型制作先检查工具能力 |
| 动画与程序效果 | 输出关键姿态、循环、插值/时序规格，以及 Shader 参数与参考画面 | 不把姿态图称为可播放动画；不把合成对照称为游戏实测；程序效果无需逐帧位图 |
| 文件验证 | 检查原生尺寸、透明度、PNG 与源文件像素一致、图集范围与 UV、模型挂点 | 保留原始生成图、源稿和否决历史；技术检查通过后仍等待用户美术审阅 |
| 采用与接入 | 用户逐项审阅造型；确认采用后进入候选交付；随后在授权的开发阶段接入并实测 | 分别记录“已采用 / 已导出 / 已接入 / 游戏验证通过”，不要混写成“完成” |

统一纹理图集主要用于滑翔伞与机械实体。独立物品与 GUI 图标先保留标准资源文件，由游戏已有图集机制处理；可共用 Aseprite 源调色板和材质层，无需为了合并几张图再建立自定义加载系统。每种材质维护阴影/中间色/高光色簇，避免强行把暖汤、树叶、金属压成同一套有限色。

## 7. 每批验收

- **2D：** 原生 1× 可辨识；32/16 同一设计；深浅背景透明边缘正常；上左受光与材质分层明确；放大只用整数倍最近邻；源稿与导出 PNG 一致。尺寸较大的实体 UV 纹理按表交付，不强制缩成 16/32。
- **HUD：** GUI 多档缩放、中英文、满/低/空/恢复、大上限、多排与吸收红心；按红心实际底边避让；底部经验条保持原位。恢复不用闪烁独占信息，低精力沿用当前 20% 阈值作为出稿基准，不在美术任务里改阈值。
- **伞：** 三视图、握点和 UV 彼此一致；检查布面上下/内外侧、图标与模型的轮廓；标准/纤细手臂、第一/第三人称、其他玩家、物品栏/装备槽/丢弃显示。第一人称抓握设计须另外开发接入。
- **角色/背负：** 抓墙、上/下/横移、放手、登顶；站立、蹲伏、游泳、滑翔；剑斧盾弓弩与手持互斥、披风/鞘翅策略、附魔/盾图案/染色。动作草稿不改变服务端规则。
- **林克时间：** 关闭/弱/标准/强、低精力、明暗背景；同场景同视角比较；瞄准中心保持清楚；可选轮廓/暗角分别可检查，轻闪/FOV 维持默认关闭。

文件检查、美术采用和游戏表现验证是三次不同的检查。此次只执行参考与采纳文件核对；没有运行上述游戏验证。

## 8. 排期和交付管理

建议以批次而非每天若干图标排期。B1 预计需要 2–4 轮视觉审阅，B2 约 2–3 轮，B3 约 1–2 轮；这是计划余量，不是日历工期保证。B4 按系统分别安排，开发未进入该系统时不批量生产资产。

正式制作阶段建议在本目录新增：`01-核心界面与滑翔伞/`、`02-角色表现/`、`03-林克时间与品牌/`、`04-后续系统储备/`、`历史版本/`。此次尚未创建这些素材目录，也未移动已有资产。每项交付包含源稿、导出、实际尺寸预览、用途/状态说明、验证记录；每批附主台账，写明与参考代码基线和上一版采用资产的关系。

本计划配套 CSV 提供 A01–A16 和后续系统的排队顺序、依赖、数量及状态。优先交付 B1，再把伞与角色表现连起来验证；料理和机械保留预算及现有储备，等待相应开发阶段启动。
