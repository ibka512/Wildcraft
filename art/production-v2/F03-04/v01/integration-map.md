# 接入映射（本轮只交付美术）

当前基线dev.14 / Java Fabric / MC26.3。此JSON为美术参数格式，不是Minecraft粒子资源codec或现有Mod配置接口。feedback-engine.js为离线审稿发射器，不是正式客户端/服务端代码；本轮不新增网络包或注册粒子类。

## 命中与格挡

FusionCombat近战AFTER_DAMAGE要求taken>0，随后effect并消费次数。额外元素反馈应绑定成功施加的效果，而不是只要次数减少就播放；死亡目标会使effect提前返回。免疫/效果未实际接受时不要伪报成功。冰addEffect与火点燃的是否生效需在后续实际接入中定义确认，现代码没有独立的FX事件或接受结果消息。

完整格挡需符合FusionShieldMixin现有damage>0且返回完全阻挡量；FusionCombat.shield还要求合格LivingEntity直接攻击者、非自身、允许PVP。投射物的直接实体不是LivingEntity，虽然原格挡与材料次数消费可能发生，但不能播放火/冰/弹性反击反馈。部分格挡不播放本版反击；通用、石、金属保持原版伤害/击退表现，不增设三套额外FX。

FusionArrowMixin在实体伤害调用前读取类别并clearArrow，再依据hurt结果和LivingEntity调用effect。未来必须在清除前保存受限类别与事件身份，成功生效后才发送视觉确认；不能等清除后再从ARROW_VIEW猜类别。箭命中方块只清除融合，不额外点燃、冻结或弹开方块，也没有持续元素拖尾。单个投射物单次确认，穿透/额外射弹不能复制融合效果或事件。

现回调不总有精确碰撞坐标：有碰撞结果时使用实际位置；近战/盾反击可取目标边界朝攻击者的近似点，并明确这是表现锚点。弹性方向取实际施加击退的有效来源方向；没有方向或没有实际施加时不虚构推力。

## 融合与拆卸

FusionActions.fuse/split完成实际物品转移后才可触发一次操作反馈。当前receive只有现有广播与系统消息，没有本版的统一FX确认事件。不得依据本地V/Shift+V按下就预播成功，也不能解析本地化系统消息、监听uses变化或假设VIEW出现必然来自新融合。重登、容器同步、材料恢复或背负重新登记不播放操作反馈。

失败、冷却拒绝、无空间、数据不可解码、滑翔/攀爬/使用物品限制继续按现有行为；不增加成功粒子或新错误音。显示资源失败而事务确实成功时，操作反馈仍可播放；缺失材料数据导致拆卸失败时不播放。正常消费耗尽不当成玩家主动拆卸，也不伪装成返还材料。

## 精灵、预算与摄像机

flame/snowflake/dust定义在原版客户端26.3资源中已验证，item_slime通过ParticleTypes注册字段核对，具体客户端提供器行为仍待接入查证。原版提供器常自带寿命/速度/颜色，不能承诺直接调用后精确满足6或8刻。需要精确控制时可共用一个内部受限粒子发射/运动层，复用原版精灵或物品碎屑；不增加美术贴图或第三方依赖。

五预设共用48在場、来源12、单次6的艺术上限；满额裁减、无排队、过期清除，尊重减少/最少粒子设置。该预算只控制本批额外反馈，其他机械、原版火焰与状态粒子必须在集成时共同实测，不能声明已实现全轮全系统预算。
